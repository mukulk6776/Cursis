Data and email operation
- New durable collections: workspace_activation, workspace_email_preferences, workspace_email_deliveries. Task.completedAt records subsequent completions; existing records are not fabricated or destructively migrated.
- Added account export/erasure scopes for the new records and optional signup attribution. Delivery records expire after 90 days.
- Weekly completion counts cover the previous Monday-Sunday in UTC; undated older completed tasks are explicitly excluded. Risk/workload are current snapshots. No capacity was stored previously: owners may configure an open estimated-hours limit. Without it, the email explicitly says overload cannot be assessed. Shared task estimates are divided equally.
- Daily digest only includes the recipient's assigned open tasks due today or flagged/overdue, with a maximum of 20 titles per list and a workspace link for the rest. Empty days send nothing.
- Existing Resend provider is reused. Missing provider/storage configuration fails visibly. Unsubscribe only confirms a durable save; preferences can explicitly resume progress email without resubscribing marketing.
- Durable send intents, leases and stable Resend keys prevent routine duplicates. Ambiguous attempts older than 23 hours require operator review because provider deduplication expires after 24 hours; monitor 503 responses. The scheduler streams workspaces in one invocation; move to a queue if runtime exceeds the host limit.
- Setup/runbook: docs/progress-emails.txt. Configure RESEND_API_KEY, RESEND_FROM_EMAIL, CRON_SECRET (a separate random 32+ character secret), deployed app URL and MongoDB. vercel.json schedules the protected report endpoint daily at 03:30 UTC. None of the three email/scheduler variables were configured in the checked local environment.
