Executive Overview

Cursis reimagines workspace productivity through autonomous ambient intelligence. Moving beyond passive Kanban boards and static CRMs, Cursis acts as an autonomous operating partner (Ordis Engine) that ingests meeting dialogues, detects project risk bottlenecks, orchestrates CRM workflows, and safely executes multi-step actions with human-in-the-loop validation.

1. Executive Summary & Core Philosophy

What is Cursis?

Cursis is a modern, high-contrast, AI-orchestrated workspace operating system tailored for high-velocity software agencies, product teams, and founders. Unlike traditional SaaS tools that require manual data entry, Cursis combines ambient intelligence with high-performance real-time interfaces.

1. Autonomous AI Intelligence (Ordis)

Continuously scans workspaces, parses raw meeting transcripts into actionable tickets, estimates timelines, and surfaces proactive approval recommendations before deadlines slip.

2. Somba Neo-Brutalist Visual System

Striking visual identity featuring high-contrast stark borders, sharp geometry, rich typography (Space Grotesk + JetBrains Mono), smooth dark modes, and micro-animations.

3. Immersive 3D Spatial Canvas

Hardware-accelerated WebGL spatial layers powered by Three.js and React Three Fiber to visualize complex multi-agent workflows and interactive project topologies.

4. Enterprise-Grade Serverless Engine

40+ dedicated serverless API route handlers deployed across global edge networks with resilient tamper-proof session token authorization and Cloud Firestore storage.

3. Detailed Platform Modules & Feature Engine

1. Ordis AI Autonomous Workspace Partner

The cornerstone of Cursis is Ordis—an autonomous multi-agent engine designed to eliminate manual management overhead. Key subsystems include:

  • Ambient Workspace Scanner (/api/ordis/ambient-scan): Continuously audits active tickets, unassigned tasks, and upcoming milestone dates to generate automated health scores.
  • Meeting Intelligence Processor (/api/ordis/process-meeting): Converts raw transcripts into structured action items, assigns owners, updates deal stages, and auto-schedules calendar follow-ups.
  • Predictive Risk Radar (/api/ordis/risk-radar): Simulates project delivery timelines based on team capacity and flags overdue risks before they impact client deliverables.
  • Autonomous Approval Queue (/api/ordis/approval-queue): Holds high-impact AI actions (sending emails, modifying client contracts, reallocating budgets) in a safety queue for 1-click human verification.

2. Executive Dashboard

Central command displaying live MRR, active sprint velocity, workload distribution charts, Ordis AI saved hours, and priority action feeds.

3. High-Velocity CRM & Deals

Complete pipeline management supporting drag-and-drop deal progression, customer contact tracking, lead scoring, and automated renewal triggers.

4. Project & Task Engine

Unified task management with multi-view modes (Kanban, List, Timeline), automated workload rebalancing, and smart dependency tracking.

5. Agency Catalog & Custom Tools

Modular tool marketplace allowing workspaces to dynamically request, build, and deploy custom internal tools via the Ordis builder API.

5. Step-by-Step Guide: How to Build Cursis from Scratch

Follow this exact chronological blueprint to recreate or extend the Cursis platform.

Step 1: System Prerequisites & Workspace Initialization

Ensure Node.js 20+ (LTS) and Git are installed. Clone the repository and install all dependencies:

# 1. Clone the repository
git clone https://github.com/mukulk6776/Cursis.git
cd Cursis

# 2. Install dependencies (Next.js 16, React 19, Three.js, Firebase)
npm install

Step 2: Firebase Console & Firestore Setup

  1. Navigate to https://console.firebase.google.com/ and create a new project (e.g. cursis-prod).
  2. Under Authentication > Sign-in method, enable Email/Password and Google Sign-In.
  3. Under Firestore Database, click Create database in Production mode.
  4. Under Project Settings > General > Your apps, register a Web App and copy the client config values (API Key, Project ID, App ID, etc.).
  5. Under Project Settings > Service accounts, click Generate new private key to download your admin credentials.

Step 3: Environment Variables Configuration

Create a file named .env.local in the root directory and populate the required keys:

# Firebase Client Configuration (Browser)
NEXT_PUBLIC_FIREBASE_API_KEY="AIzaSy..."
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN="cursis-prod.firebaseapp.com"
NEXT_PUBLIC_FIREBASE_PROJECT_ID="cursis-prod"
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET="cursis-prod.appspot.com"
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID="123456789"
NEXT_PUBLIC_FIREBASE_APP_ID="1:123456789:web:abcdef"

# Firebase Admin SDK Configuration (Serverless Routes)
FIREBASE_PROJECT_ID="cursis-prod"
FIREBASE_CLIENT_EMAIL="firebase-adminsdk-xxxxx@cursis-prod.iam.gserviceaccount.com"
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvgIBADANBgk...=\n-----END PRIVATE KEY-----\n"

# Session Security & AI Secrets
AUTH_SESSION_SECRET="generate_a_random_32_character_secret_key"
GEMINI_API_KEY="AIzaSy..."

Step 4: Next.js & Serverless Bundling Configuration

Ensure next.config.ts contains serverExternalPackages: ['firebase-admin'] to prevent Turbopack native gRPC bundling errors on Vercel:

import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  reactStrictMode: false,
  devIndicators: false,
  serverExternalPackages: ['firebase-admin'],
  experimental: {
    optimizePackageImports: ['lucide-react', 'framer-motion', 'three', '@react-three/fiber', '@react-three/drei'],
  },
};

export default nextConfig;

6. Running Locally & Production Deployment

Local Development & Production Verification

# Start local dev server (Hot reload enabled on http://localhost:3000)
npm run dev

# Run strict TypeScript and Next.js production build check
npm run build

# Launch local production server
npm run start

Deploying to Vercel (Edge Platform)

  1. Push your latest changes to GitHub: git push origin main.
  2. Go to https://vercel.com/new and import your Cursis repository.
  3. In the Environment Variables section, paste all values from your .env.local.
  4. Click Deploy. Vercel will compile all 47 routes and deploy the application globally.
  5. In Firebase Console > Authentication > Settings > Authorized domains, add your Vercel deployment URL (e.g. cursis.vercel.app) to allow Google OAuth popups.

7. Engineering Best Practices & Architecture Reference

Resilient Session Exchange

The /api/auth/session endpoint returns a self-contained, signed session token embedded in an HttpOnly cookie with SameSite=lax. This eliminates reliance on blocking remote roundtrips during critical serverless invocations.

3D WebGL Performance

Three.js canvas contexts are wrapped with lazy loading and dynamic imports (next/dynamic with ssr: false) to ensure fast First Contentful Paint (FCP) and zero main-thread blocking.
